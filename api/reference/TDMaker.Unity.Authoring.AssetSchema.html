Remarks

Version rule. Each versioned asset serializes an int with no initializer. Unity keeps the C# initializer when a field is missing from an old file, so a 1.0 file reads 0. A brand-new asset (ScriptableObject.CreateInstance, a Create menu, New Level, Unit Workshop) is never deserialized before its first serialization; HandleBeforeSerialize(IVersionedAsset) stamps such an asset with the current version, so it is saved as current without any change to the creation code. MarkCurrent(IVersionedAsset) stamps explicitly. Because 0 can also mean "made in code and never stamped", every step must be idempotent: running it on data that is already in the new shape must change nothing.

Steps. A step registered at fromVersion brings data from that version to fromVersion + 1. A type's current version is one past its highest registered step, and at least BaselineVersion. Steps registered for a base type also run for its subclasses (base first). Register from the asset type's static constructor; the framework runs the static constructors of the whole type hierarchy before it reads the registry.

On load. HandleAfterDeserialize(IVersionedAsset) runs the missing steps in memory, in order, but does not change the stored version: the file on disk is still old until it is upgraded and saved (NeedsUpgrade(Object), Upgrade(Object)). Steps run inside OnAfterDeserialize, possibly off the main thread, so they must only touch the asset's serialized fields: no Unity API (no name, no AssetDatabase, no Object == null on other objects). A migration that needs Unity API belongs in the asset's OnEnable or in an editor upgrade pass instead.

Newer data. An asset whose version is greater than the code's current version is refused: no step runs, the version is never lowered, and IsNewerThanSupported(Object) reports it.

Renaming fields (FormerlySerializedAs policy). A renamed serialized field must keep [UnityEngine.Serialization.FormerlySerializedAs("oldName")] for as long as older data may exist; never remove it. A rename alone needs no step. When the meaning of data changes (units, ranges, a field split or merged, a value moved elsewhere), keep the old field readable (hidden), and add a step that converts it and clears it, as the level's legacy star rule does.
